# ADVENTURE PiPi SEOリライト

工程は3段階。人が判断するのは②の1回だけ。

## ① 入力と自動分析（質問は最小限）

1. 受け取るもの：ターゲットKW、記事URL。任意で現行WP本文HTML、GSCクエリ（CSV・貼り付け）。KWとURLがあれば質問せず進む。
2. 対象島を URL のドメインで判定し、`islands/<島>.json` **だけ**を読む。他島のjsonは読まない。
3. 現行記事を取得し、H2/H3・文字数・リンク・画像・ショートコードを把握する。現行HTMLが貼られていればそれを正とする。
4. 検索上位を調べ、日本語・広告除外・同一ドメイン重複除外で5記事を選び、**本文の見出し構成**を取得して比較する。
   - 順位は「検索日時点の参考値」と明記。PAAが確認できなければ「関連質問（推定）」と書き、PAAと断定しない。
5. GSCクエリがあれば「表示回数が多いのにCTRが低い」「11〜30位」のクエリを最優先の狙いにする。

## ② 戦略（ここで止めてOKをもらう）

1画面で次を出す。前置きや一般論は書かない。

- **狙うクエリ**：GSCの数値があれば併記。推定流入改善率などの根拠のない数字は書かない。
- **施策**：最大8件。各施策は「どのH2/H3に・何を・どう」を1〜2行で書き、優先度（高中低）を付ける。次の観点は必ず含める：サジェストKWの配置、関連質問のFAQ化、上位記事との差分、E-E-A-T（PiPiが書ける一次情報）、内部リンク、ツアー導線、島別情報の正確性。
- **見出し構成（改訂後のみ）**：各行に1行の理由。最後は `<h2>さいごに</h2>`。
- **タイトル3案**（文字数・KW位置・現行との差分）と**ディスクリプション3案**（120〜130字）。
- **技術SEOの要対応項目**：実際に必要なものだけ。

「OK」で③へ。修正依頼があれば②の中で直す。

## ③ 本文生成 → 自動検証 → 出力

1. `rules/writing-rules.md` と `rules/html-rules.md` に従い、本文・FAQ・内部リンク・CTAを**一括で**生成する。FAQは `rules/faq-template.html` の形をそのまま使う。
2. あいさつ文、CTAボタン、ブランドカラーは島jsonの値をそのまま貼る。書き換えない。
3. リンクURLは島jsonの `tours` / `columns` / `activity_url` にあるものだけを使う。無ければ `activity_url` に誘導する。
4. 生成したHTMLをファイルに保存し、検証する：

   ```bash
   python3 .claude/skills/pipi-rewrite/scripts/validate.py <出力.html> --island <ishigaki|miyako|iriomote> [--original <現行.html>]
   ```

   - `ERROR` が0になるまで直して再検証する。`WARN` は内容を確認し、必要なら直す。
   - 検証結果を通さずにHTMLをユーザーへ渡さない。
5. 出力：変更点の要約（残した内容／追加／削除・統合）→ 推奨タイトル → 検証済みHTML全文 → 検証結果の要約。

## 守ること

- 推測でツアーURL・料金・営業時間・住所・電話・フェリー時刻・対象年齢・送迎条件を書かない。確認できない事実は書かないか、公式サイトでの確認を促す。
- 完成本文に競合ショップ名、出典記号（contentReference / oaicite 等）を入れない。
- 現行記事の画像・ショートコード・表・既存CTA・内部リンクは原則残す。現行HTMLが無い場合は本文の外に「既存の画像・埋め込み・ショートコードは現行記事の該当位置に残したまま本文のみ差し替えてください。」と書く。
- 西表島は、石垣島からの船移動・島内移動・宿泊場所・フェリー時刻の確認を必要に応じて促す。
